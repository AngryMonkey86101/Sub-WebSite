# Портал семейного VPN

Члены семьи сами получают ключи AmneziaVPN для своих устройств по личной ссылке. Портал работает поверх [amnezia-api](https://github.com/kyoresuas/amnezia-api) — REST-доступа к контейнерам Amnezia на том же VPS. Общий план — в [docs/PLAN.md](../docs/PLAN.md).

- **Технологии:** Node.js 22.13+ без внешних зависимостей (`node:http`, `node:sqlite`, `node:crypto`, `node:zlib`). Данные — SQLite на томе Docker. HTTPS — Caddy, сертификат выпускается и продлевается сам.
- **Обезличенность:**
  - участник — случайный код (`K7M2`), имён и контактов нет;
  - ключ на сервере Amnezia называется «код-номер» (`K7M2-2`);
  - IP-адреса устройств портал отбрасывает сразу при получении от amnezia-api;
  - журналы запросов не ведутся.
- **Ключи VPN** в базе зашифрованы AES-256-GCM ключом из `.env`.
- **Протоколы:** пока только AmneziaWG. Поддержка Xray (VLESS + REALITY) в коде есть, но отложена — см. «Позже: Xray».
- **Telegram-бот админа:** уведомления и команды (`/status`, `/invite`, …). В сообщениях только коды участников.

## Как это устроено для семьи

1. Админ создаёт приглашение (в админке или командой CLI) и передаёт ссылку лично.
2. Человек открывает ссылку и нажимает «Получить доступ». Он получает личную ссылку, её нужно сохранить.
3. В кабинете человек выбирает платформу и получает ключ `vpn://` и QR-код для приложения AmneziaVPN. Лимит по умолчанию — 4 устройства.
4. Ненужное устройство человек отзывает сам. Админ может поставить участника на паузу (ключи выключаются, но не меняются), удалить его или выдать новую ссылку взамен потерянной.
5. Тем, кому неудобно заходить на портал, админ выдаёт ключ сам: «Выдать ключ» в админке. Ключ хранится у админа в «Моих устройствах» с меткой «для кого» (например, «кухня-планшет»). Метка видна только в портале: на VPN-сервер и в Telegram она не уходит. Лимита устройств у админа нет.
6. Ярлык на экране «Домой» — в кабинете кнопка «Добавить на экран „Домой“». В Chrome на Android она открывает системное окно установки, на iPhone и в других браузерах показывает инструкцию. Ярлык ведёт на личную ссылку, поэтому работает и на iPhone, где ярлык не видит вход, сохранённый в Safari. После новой личной ссылки ярлык добавляют заново.
7. У админа в шапке — «Мои устройства» и «Админка», в админке — «Выйти из админки», после выдачи ключа — «Выдать ещё ключ».
8. В админке видны и ключи, выданные мимо портала: в приложении Amnezia вручную и подключение самого приложения (раздел «Ключи вне портала»). Портал ими не управляет — пауза и отзыв в приложении Amnezia.
9. Если IP сервера сменится, портал сам направит имена DuckDNS на новый IP и напишет админу в Telegram. Ключи у семьи прежние: VPN достаточно выключить и включить.
10. Если сервер станет недоступен, GitHub заметит это за 15 минут, перепроверит в течение 5 минут и пришлёт админу в Telegram «🔴 Сервер недоступен».
11. Раз в сутки бот присылает админу зашифрованный бэкап. С ним сервер можно поднять заново на другом VPS, и ключи у семьи не изменятся.

## Установка на VPS (этап 1)

Пример для VPS AmneziaHost с Ubuntu. Команды выполняются под root, если не сказано иное.

### 1. Имена DuckDNS

1. На [duckdns.org](https://www.duckdns.org) заведите отдельный аккаунт и два случайных имени, без слов «vpn» и «family»:
   - `<имя-vpn>` — адрес сервера в ключах;
   - `<имя-портала>` — сайт.
2. Укажите для обоих IP сервера. Пока вручную; автоматическое обновление — этап 3 плана.
3. Проверьте, что имя находится и ведёт на сервер, и не только с самого сервера, а **с вашего компьютера или телефона в России без VPN**. Если не так — см. «Не подключается по имени DuckDNS» ниже.
   ```bash
   nslookup -debug <имя-vpn>.duckdns.org
   ```
   В ответе должен быть IP сервера, не должно быть записи AAAA (IPv6). Заодно посмотрите TTL.

### 2. AmneziaWG

Нужен контейнер `amnezia-awg2` — тот же, что ставит приложение Amnezia.

- **Через приложение Amnezia:** добавьте сервер **по IP** и установите AmneziaWG. По IP надёжнее: приложение админа не зависит от DNS. Имя DuckDNS в ключи семьи подставляет amnezia-api (`VPN_HOST` в `.env`), а не приложение.
- **Без приложения:** [amnezia-protocols](https://github.com/kyoresuas/amnezia-protocols).
  ```bash
  curl -fsSL https://raw.githubusercontent.com/kyoresuas/amnezia-protocols/main/install.sh | bash -s -- awg
  ```

Если Xray уже установлен (приложением или хостингом) и занимает порт 443, удалите его — порт 443 нужен порталу. Удалить можно в приложении Amnezia (настройки сервера → протоколы) или командой `docker rm -f amnezia-xray`. Xray вернём позже на другом порту.

Проверьте, что порты 80 и 443 свободны и какой порт у AmneziaWG:

```bash
ss -ltnup | grep -E ':(80|443)\b'      # должно быть пусто
docker ps --format '{{.Names}}\t{{.Ports}}'
```

### 3. Пользователь для выкладки и фаервол

1. Пользователь `deploy` с правом запускать Docker:
   ```bash
   adduser --disabled-password deploy && usermod -aG docker deploy
   ```
2. На своём компьютере: `ssh-keygen -t ed25519 -f family-vpn-deploy -C github-actions`. Содержимое `family-vpn-deploy.pub` добавьте в `/home/deploy/.ssh/authorized_keys`.
3. Фаервол: SSH, HTTP/HTTPS портала и UDP-порт AWG (по умолчанию 55424, смотрите вывод `docker ps`).
   ```bash
   ufw allow 22/tcp && ufw allow 80,443/tcp && ufw allow 443/udp && ufw allow 55424/udp && ufw enable
   ```

### 4. Настройки портала

На сервере под `deploy` (из-под root: `su - deploy`) скачайте репозиторий и скопируйте файлы портала в `~/family-vpn`:

```bash
git clone --depth 1 --branch main https://github.com/AngryMonkey86101/Sub-WebSite.git ~/sub-website
mkdir -p ~/family-vpn && cp -r ~/sub-website/server/. ~/family-vpn/
ls -a ~/family-vpn
```

- В выводе `ls` должны быть `docker-compose.yml` и `.env.example`.
- Если `git` не установлен — под root: `apt install -y git`.

Обновить портал позже, пока не настроена выкладка из GitHub Actions (шаг 7):

```bash
git -C ~/sub-website pull && cp -r ~/sub-website/server/. ~/family-vpn/
```

```bash
cd ~/family-vpn && docker compose up -d --build
```

Файл `.env` и база при этом не затрагиваются. Все команды `docker compose` выполняются из папки `~/family-vpn`, иначе Docker ответит «no configuration file provided».

`.env` — файл настроек и секретов. `docker compose` читает его сам из той же папки, в репозиторий он не попадает. Создайте его одной командой: подставьте свои имена DuckDNS в первые две строки `sed`, остальное она сгенерирует и определит сама. Если `.env` уже есть, команда его не тронет — иначе новые секреты затёрли бы старые.

```bash
cd ~/family-vpn
if [ -e .env ]; then echo "Файл .env уже есть — не перезаписываю"; else
cp .env.example .env && chmod 600 .env && sed -i \
  -e "s|^PORTAL_HOST=.*|PORTAL_HOST=<имя-портала>.duckdns.org|" \
  -e "s|^VPN_HOST=.*|VPN_HOST=<имя-vpn>.duckdns.org|" \
  -e "s|^AMNEZIA_API_KEY=.*|AMNEZIA_API_KEY=$(openssl rand -hex 32)|" \
  -e "s|^SERVER_ID=.*|SERVER_ID=$(cat /proc/sys/kernel/random/uuid)|" \
  -e "s|^DOCKER_GID=.*|DOCKER_GID=$(stat -c '%g' /var/run/docker.sock)|" \
  -e "s|^DOCKER_API_VERSION=.*|DOCKER_API_VERSION=$(docker version --format '{{.Server.APIVersion}}')|" \
  -e "s|^KEY_ENCRYPTION_KEY=.*|KEY_ENCRYPTION_KEY=$(openssl rand -base64 32)|" \
  .env && echo "Готово"; fi
```

Проверьте результат: `grep -v '^#' .env`. Ни одна строка, кроме `TELEGRAM_*`, не должна быть пустой.

| Строка | Что это | Откуда |
|---|---|---|
| `PORTAL_HOST` | Имя сайта портала | Второе имя DuckDNS. Можно то же, что `VPN_HOST`: всё заработает, но имя VPN попадёт в публичный журнал сертификатов |
| `VPN_HOST` | Адрес сервера в ключах семьи | Имя DuckDNS из шага 1 |
| `PROTOCOLS`, `DEFAULT_DEVICE_LIMIT` | Протоколы и лимит устройств | Оставить как есть |
| `AMNEZIA_API_KEY` | Пароль, с которым портал обращается к amnezia-api; вводить его никуда не нужно | `openssl rand -hex 32` — 64 символа |
| `AMNEZIA_API_VERSION` | Версия amnezia-api | Оставить `2.0.0` |
| `SERVER_ID` | Идентификатор сервера для amnezia-api | Случайный UUID |
| `DOCKER_GID` | Группа файла `docker.sock`: без неё amnezia-api не управляет контейнерами Amnezia | `stat`, обычно число вроде `988` или `999` |
| `DOCKER_API_VERSION` | Версия Docker на сервере | `docker version`, вроде `1.51` |
| `KEY_ENCRYPTION_KEY` | Ключ, которым портал шифрует выданные ключи VPN в своей базе | `openssl rand -base64 32` — 44 символа, на конце `=` |
| `TELEGRAM_BOT_TOKEN` | Токен бота админа | Пока пусто, шаг 6 |
| `TELEGRAM_CHAT_ID` | Чат для уведомлений, заданный вручную | Обычно пусто: чат подключается из админки |
| `DUCKDNS_TOKEN` | Токен DuckDNS для сторожа IP | Пока пусто, шаг 7 |
| `BACKUP_AGE_RECIPIENT` | Открытый ключ age, которым шифруются бэкапы | Пока пусто, шаг 10 |

**Сохраните `.env` в менеджер паролей** (KeePassXC, Bitwarden и т. п.) как защищённую заметку «Семейный VPN — .env»: выведите файл командой `cat .env` и скопируйте текст. Почему это важно:

- **`KEY_ENCRYPTION_KEY` — единственное, что нельзя восстановить.** Ключи VPN портал хранит только зашифрованными этим ключом. Если ключ потерян или заменён, кнопка «Показать ключ» перестанет работать у всех устройств. VPN на устройствах при этом продолжит работать, но для нового телефона или переустановки приложения придётся отзывать ключ и выдавать новый. Поэтому `KEY_ENCRYPTION_KEY` после выдачи первых ключей не меняют.
- **Остальное заменимо:** `AMNEZIA_API_KEY` и `SERVER_ID` можно сгенерировать заново, `DOCKER_*` — определить заново, токен бота — перевыпустить у @BotFather. После замены — `docker compose up -d`.
- **Никому не пересылайте `.env`**, не вставляйте в чаты и не добавляйте в репозиторий. Полный бэкап сервера — этап 4 плана.

### 5. Запуск и проверка

```bash
docker compose up -d --build
docker compose ps
docker compose exec portal npm run -s cli -- check --keys
```

`check --keys` проверяет:

- **DNS:** ведут ли имена DuckDNS на этот сервер (сверяет с его внешним IP) и нет ли у них IPv6;
- **amnezia-api:** связь и список протоколов;
- **ключи:** создаёт пробный ключ, показывает, с каким адресом он собран, и сразу удаляет. Должно быть имя `<имя-vpn>.duckdns.org`, а не IP.

Строки с ⚠️ — то, что нужно исправить.

Первый админ:

```bash
docker compose exec portal npm run -s cli -- invite --admin
```

Откройте ссылку на телефоне, нажмите «Получить доступ», сохраните личную ссылку. Добавьте своё устройство и проверьте подключение в AmneziaVPN. Админка — по ссылке «админка» в шапке.

### 6. Telegram-бот

Бот присылает админу уведомления и выполняет несколько команд. Сообщения боту портал забирает сам, поэтому входящие подключения и дополнительные порты не нужны.

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, придумайте имя и логин бота (логин заканчивается на `bot`). BotFather пришлёт токен вида `123456789:AA…`.
2. Впишите токен в `.env`. Команда спросит токен и не покажет его на экране и в истории команд:
   ```bash
   cd ~/family-vpn && read -rsp 'Токен бота: ' T && sed -i "s|^TELEGRAM_BOT_TOKEN=.*|TELEGRAM_BOT_TOKEN=$T|" .env && unset T && echo && docker compose up -d
   ```
3. Админка → раздел «Telegram» (внизу страницы) → «Подключить Telegram» → «Открыть Telegram». В чате с ботом нажмите «Запустить». Бот ответит «Бот подключён».
4. Проверка — кнопка «Проверить» в админке или `docker compose exec portal npm run -s cli -- check`.

Ссылка для подключения одноразовая и действует 10 минут. Если не успели — нажмите «Подключить Telegram» ещё раз.

**Команды бота:**

| Команда | Что делает |
|---|---|
| `/status` | Отвечает ли сервер VPN, сколько ключей и сколько устройств подключено сейчас, сколько участников |
| `/members` | Коды участников, их состояние и число устройств |
| `/invite` | Новый участник и приглашение на 3 дня; `/invite 2` — с лимитом 2 устройства |
| `/relink КОД` | Новое приглашение тому, кто потерял личную ссылку; ключи на устройствах остаются |
| `/help` | Список команд |

**Уведомления:**

- о запуске портала (так видны и неожиданные перезагрузки сервера);
- о приглашении, которое открыли;
- о выданных и отозванных ключах;
- о паузе и удалении участников;
- о сбоях amnezia-api;
- о ключе, который собран с IP вместо имени DuckDNS.

**Безопасность:**

- Команды бот выполняет только из подключённого личного чата. Остальным он отвечает, что бот закрытый.
- Кто управляет этим чатом, может приглашать людей. Включите в Telegram облачный пароль: Настройки → Конфиденциальность → Облачный пароль. Личную ссылку админа бот не выдаёт.
- В Telegram уходят только коды участников: без меток, имён и IP. Приглашения из бота проходят через серверы Telegram, но они одноразовые и живут 3 дня.
- Если токен попал не туда: @BotFather → `/revoke` → новый токен — снова шаг 2. Чат переподключать не нужно.
- Уведомления в группу: впишите id группы в `TELEGRAM_CHAT_ID`. Тогда подключать чат из админки не нужно, но команды не работают: в группе их мог бы отправить любой участник.

### 7. Сторож IP

Если IP сервера сменится — например, AmneziaHost поменяет его по тикету из-за блокировки, — портал за минуту-две сам направит имена DuckDNS на новый IP и напишет в Telegram. Ключи у семьи не меняются.

1. На [duckdns.org](https://www.duckdns.org) войдите в аккаунт, где ваши имена, и скопируйте `token` вверху страницы.
2. Впишите токен в `.env`. Команда спросит его и не покажет на экране и в истории. Заодно она закроет `.env` от других пользователей сервера:
   ```bash
   cd ~/family-vpn && { grep -q '^DUCKDNS_TOKEN=' .env || echo 'DUCKDNS_TOKEN=' >> .env; } && read -rsp 'Токен DuckDNS: ' T && sed -i "s|^DUCKDNS_TOKEN=.*|DUCKDNS_TOKEN=$T|" .env && unset T && echo && chmod 600 .env && docker compose up -d
   ```
3. Через минуту проверьте: админка → «Адрес сервера» показывает «Всё в порядке». То же в `/status` у бота и командой:
   ```bash
   docker compose exec portal npm run -s cli -- duckdns
   ```

**Как работает:**

- **Раз в минуту** портал узнаёт внешний IPv4 у трёх сервисов: ipify, icanhazip и Amazon. Он верит адресу, который назвали хотя бы два из них. Затем смотрит, куда ведут имена из `VPN_HOST` и `PORTAL_HOST`.
- **Имя ведёт на прежний IP этого сервера** — значит, IP сменился. Портал обновляет DuckDNS: оба имени одним запросом, только IPv4. В Telegram приходит «IP сервера сменился: старый → новый».
- **Имя ведёт на чужой адрес** — сторож его не трогает и пишет предупреждение. Так после переезда старый сервер не перебьёт новый. Направить имя на этот сервер можно кнопкой «Направить DuckDNS сюда» в админке или командой `duckdns --takeover`.
- **Сбои** (не отвечают сервисы IP, DNS или DuckDNS) приходят в Telegram, только если длятся дольше 10 минут.

**Если IP заблокировали:**

1. Напишите тикет в AmneziaHost.
2. Дождитесь в Telegram сообщения «IP сервера сменился».
3. Скажите семье выключить и включить VPN. Если сразу не подключается — подождать 5 минут, пока обновятся кэши DNS, и повторить.

Выкладку из GitHub Actions менять не нужно: в ней указано имя, а не IP.

### 8. Выкладка из GitHub Actions

Settings → Secrets and variables → Actions:

- `SERVER_HOST` — `<имя-портала>.duckdns.org` (имя, а не IP: IP может смениться);
- `SERVER_USER` — `deploy`;
- `SERVER_SSH_KEY` — содержимое закрытого ключа `family-vpn-deploy`;
- `SERVER_KNOWN_HOSTS` — вывод `ssh-keyscan <имя-портала>.duckdns.org`.

После этого каждый пуш с изменениями в `server/` проверяется тестами и сборкой образа. Пуш в `main` ещё и выкладывается на сервер (workflow `.github/workflows/server.yml`). Файл `.env` и база на сервере при выкладке не трогаются.

### 9. Проверка доступности

Упавший сервер сам о себе не сообщит, поэтому его проверяет GitHub (`.github/workflows/monitor.yml`):

- раз в 15 минут GitHub Actions открывает портал по имени DuckDNS;
- если портал не отвечает, проверка повторяется каждую минуту в течение 5 минут;
- если связь так и не вернулась, в Telegram приходит «🔴 Сервер недоступен» с причиной: не находится имя, сервер не отвечает, ошибка портала и т. п.;
- пока сервер недоступен, раз в час приходит напоминание, а когда вернётся — «🟢 Сервер снова доступен».

Настройка:

1. Узнайте id чата: админка → раздел «Telegram», строка «id чата».
2. GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret. Нужны три секрета:
   - `MONITOR_HOST` — имя портала, `<имя-портала>.duckdns.org`, без `https://`;
   - `TELEGRAM_BOT_TOKEN` — токен бота, тот же, что в `.env`;
   - `TELEGRAM_CHAT_ID` — id чата из пункта 1.
3. Проверьте: GitHub → Actions → «Доступность сервера» → Run workflow. Через минуту бот пришлёт «✅ Проверка доступности: сервер отвечает». В админке в разделе «Адрес сервера» появится «Внешняя проверка доступности: последняя — только что».

Что важно знать:

- **Что проверяется.** Весь путь до портала: имя DuckDNS, сеть до VPS, Caddy и портал. Сам VPN-контейнер проверка не видит: AmneziaWG не отвечает на запросы извне.
- **Опоздания.** GitHub запускает расписание с задержкой — обычно несколько минут, иногда до получаса.
- **Письма от GitHub.** Пока сервер недоступен, запуски проверки завершаются с ошибкой: так следующий запуск узнаёт, что сервер «лежит». GitHub может присылать об этом письма — это второй канал, если недоступен и Telegram. Отключить письма: GitHub → Settings → Notifications → Actions.
- **60 дней без изменений.** В публичном репозитории GitHub отключает расписание, если 60 дней не было изменений, и перед этим присылает письмо. Портал следит за этим сам: если внешняя проверка не приходила больше 2 часов, бот предупредит. Включить снова: Actions → «Доступность сервера» → Enable workflow.
- **Журналы запусков** публичного репозитория видны всем. Имя сервера и IP скрипт в них не пишет, значения секретов GitHub скрывает сам.
- **Токен бота сменили** у @BotFather — обновите и секрет `TELEGRAM_BOT_TOKEN`.

### 10. Бэкап

Раз в сутки бот присылает в Telegram файл `family-vpn-ГГГГ-ММ-ДД.tar.gz.age`, без звука. В нём всё, чтобы поднять сервер заново с прежними ключами: ключи сервера AmneziaWG, база портала и настройки `.env`. Файл зашифрован вашим открытым ключом age. Расшифровать его можно только закрытым ключом, а он есть только у вас: ни Telegram, ни тот, кто получит файл, его не прочитают.

1. После обновления пересоберите портал — в образ добавлена программа age:
   ```bash
   cd ~/family-vpn && docker compose up -d --build
   ```
2. Создайте пару ключей. Команда покажет три строки и ничего не сохранит на сервере:
   ```bash
   docker compose exec portal age-keygen
   ```
   ```
   # created: 2026-11-01T12:00:00Z
   # public key: age1…
   AGE-SECRET-KEY-1…
   ```
   **Все три строки** сохраните в менеджер паролей, например как «Семейный VPN — ключ бэкапов». Без строки `AGE-SECRET-KEY-1…` бэкапы не расшифрует никто, включая вас. Потом очистите экран командой `clear`.
3. Впишите в `.env` открытый ключ — строку `age1…` из строки `# public key:`. Он не секретный. Затем перезапустите портал:
   ```bash
   cd ~/family-vpn && { grep -q '^BACKUP_AGE_RECIPIENT=' .env || echo 'BACKUP_AGE_RECIPIENT=' >> .env; } && read -rp 'Открытый ключ age (age1…): ' K && sed -i "s|^BACKUP_AGE_RECIPIENT=.*|BACKUP_AGE_RECIPIENT=$K|" .env && docker compose up -d
   ```
4. Первый бэкап придёт в течение 10 минут. Сразу — кнопкой «Сделать бэкап сейчас» в админке (раздел «Бэкап») или командой `/backup` у бота.
5. В подписи к файлу есть «Зашифрован ключом age1xxxxxx…yyyyyy». Начало и конец должны совпасть с открытым ключом в менеджере паролей.

Что важно знать:

- **Нужен бот** (шаг 6): бэкап уходит в его чат.
- **Не удалось** — сообщение в бот, следующая попытка через час.
- **Старые бэкапы бот удалить не может:** Telegram разрешает ботам удалять только сообщения младше 48 часов. Файлы маленькие; раз в несколько месяцев их можно почистить вручную, оставив последние.
- **Бэкап в файл на сервере** — для переезда, пока старый сервер работает. Флаг `-T` обязателен, иначе файл испортится:
  ```bash
  cd ~/family-vpn && docker compose exec -T portal npm run -s cli -- backup --stdout > ~/family-vpn-backup.tar.gz.age
  ```
- **Ключ age не меняйте без нужды.** Если сменили, старые бэкапы откроются только старым закрытым ключом — храните оба.
- **Что не входит:** SSH-ключи сервера. Портал работает в контейнере и их не видит.

## Восстановление из бэкапа

Расшифровать бэкап и посмотреть, что внутри, можно на любом Linux, в том числе на новом VPS:

```bash
sudo apt install -y age
```

Создайте файл с закрытым ключом: выполните команду, вставьте три строки из менеджера паролей и нажмите Ctrl+D:

```bash
cat > ~/backup-key.txt && chmod 600 ~/backup-key.txt
```

Расшифруйте и распакуйте — вместо `family-vpn-2026-11-01.tar.gz.age` подставьте имя своего файла:

```bash
mkdir -p ~/restore && age -d -i ~/backup-key.txt family-vpn-2026-11-01.tar.gz.age | tar xz -C ~/restore && ls ~/restore
```

В Windows понадобится `age.exe` со страницы [релизов age](https://github.com/FiloSottile/age/releases). Затем выполните `age -d -i backup-key.txt family-vpn-….tar.gz.age > backup.tar.gz` и `tar xzf backup.tar.gz`: `tar` встроен в Windows 10 и новее.

Внутри четыре файла:

| Файл | Что это |
|---|---|
| `env` | Настройки `.env`. `DOCKER_GID` и `DOCKER_API_VERSION` на новом сервере определяются заново (шаг 4) |
| `amnezia.json` | Ключи и клиенты сервера AmneziaWG; на новом сервере загружаются через amnezia-api `POST /server/backup` |
| `portal.sqlite` | База портала: участники, выданные ключи, настройки бота и сторожа |
| `README.txt` | Описание этих файлов |

Пошаговый переезд на новый VPS из такого бэкапа — следующая часть этапа 4: скрипт `migrate.sh` и `RUNBOOK.md`. После работы удалите `~/backup-key.txt` и `~/restore`: там закрытые ключи.

## Не подключается по имени DuckDNS

Если по IP сервер доступен, а по имени `<имя>.duckdns.org` — нет, дело в DNS. Выясните, что видит ваша сеть.

**1. С сервера** (после шага 5):

```bash
docker compose exec portal npm run -s cli -- check
```

Здесь видно, на какой IP ведут имена и есть ли у них IPv6.

**2. С компьютера в России без VPN** — через DNS провайдера, Яндекса и Google:

```bash
nslookup <имя-vpn>.duckdns.org
nslookup <имя-vpn>.duckdns.org 77.88.8.8
nslookup <имя-vpn>.duckdns.org 8.8.8.8
```

| Что видно | Что это значит | Что делать |
|---|---|---|
| Везде IP сервера | DNS в порядке | Ищите причину в порту и фаерволе: UDP-порт AWG открыт, в приложении указан верный порт |
| Везде другой IP | Запись на duckdns.org указывает не туда. Например, имя создавали с домашнего компьютера или через VPN, и сохранился их адрес | Впишите IP сервера на duckdns.org и нажмите «update ip» |
| Есть адрес IPv6 | Устройство без IPv6 может пойти по нему и не подключиться | Очистите поле ipv6 на duckdns.org |
| У провайдера пусто или ошибка, у 77.88.8.8 или 8.8.8.8 — IP сервера | DNS провайдера не находит или подменяет имена DuckDNS | DuckDNS не подходит для этой сети. Нужно своё доменное имя у DNS-хостинга с API (план, раздел 12) |
| Нигде не находится | Запись не создана, или до серверов DuckDNS нет доступа | Проверьте имя на duckdns.org. Если там всё верно — то же, что в строке выше |

Пока ключи семье не выданы, имя меняется без последствий: впишите новое в `VPN_HOST` и выполните `docker compose up -d`.

## Позже: Xray

Поддержка Xray (VLESS + REALITY) в портале есть, но выключена. Включение:

1. Поставьте Xray **не на 443** (порт занят порталом), например на 8443. `--force` создаёт новые ключи сервера Xray — после выдачи ключей Xray семье так делать нельзя.
   ```bash
   curl -fsSL https://raw.githubusercontent.com/kyoresuas/amnezia-protocols/main/install.sh | bash -s -- xray --port 8443 --force
   ```
2. Откройте порт: `ufw allow 8443/tcp`.
3. В `.env` укажите `PROTOCOLS=amneziawg3,xray`, затем выполните `docker compose up -d`.
4. Проверьте: `docker compose exec portal npm run -s cli -- check --keys`.

В кабинете появится выбор протокола: «AmneziaWG — основной» и «Xray — если основной не подключается».

**Трафик Xray в админке** (необязательно). Xray не сообщает о рукопожатиях, а трафик amnezia-api видит только при включённой статистике Xray. Включить её можно скриптом из amnezia-api. Скрипт меняет `server.json` и сохраняет прежний как `server.json.bak`; контейнер перезапускается, клиенты Xray отключаются на несколько секунд.

```bash
git clone --depth 1 --branch v2.0.0 https://github.com/kyoresuas/amnezia-api.git /tmp/amnezia-api
docker exec amnezia-xray cat /opt/amnezia/xray/server.json > /tmp/server.json
python3 /tmp/amnezia-api/scripts/xray/setup_xray_stats.py /tmp/server.json   # changed или unchanged
docker exec amnezia-xray cp /opt/amnezia/xray/server.json /opt/amnezia/xray/server.json.bak
docker cp /tmp/server.json amnezia-xray:/opt/amnezia/xray/server.json && docker restart amnezia-xray
```

Последние две команды нужны, только если скрипт ответил `changed`.

## Команды CLI

На сервере запускаются в контейнере портала: `docker compose exec portal npm run -s cli -- <команда>`.

| Команда | Что делает |
|---|---|
| `invite [--admin] [--devices N]` | Новый участник и приглашение на 3 дня |
| `relink КОД` | Новое приглашение взамен потерянной ссылки; прежние ссылки перестают работать, ключи остаются |
| `list` | Участники и их устройства |
| `duckdns [--takeover]` | Сторож IP: проверить записи DuckDNS сейчас; с `--takeover` — направить имена на этот сервер (после переезда) |
| `backup [--stdout]` | Бэкап сейчас — в Telegram; с `--stdout` — зашифрованный архив в файл (запускать с `exec -T`) |
| `check [--keys]` | Имена DuckDNS, бот Telegram, связь с amnezia-api; с `--keys` — пробный ключ каждого протокола |
