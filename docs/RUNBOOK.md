# Что делать, если…

Короткая памятка админа. Подробности — в [server/README.md](../server/README.md). Команды на сервере выполняются под `deploy` из папки `~/family-vpn`; команды портала — `docker compose exec portal npm run -s cli -- <команда>`.

## Семье: VPN не подключается

Почти всегда помогает **выключить и включить VPN** в приложении AmneziaVPN. После смены IP уже поднятый туннель новый адрес не узнаёт. Если не помогло сразу — подождать 5 минут, пока обновятся кэши DNS, и повторить.

Если не подключается ни у кого — посмотрите `/status` у бота:

- **Бот не отвечает** — сервер недоступен, см. ниже.
- **«⚠️ amnezia-api не отвечает»** — на сервере: `docker compose ps` и `docker compose up -d`.
- **«⚠️ Имя DuckDNS указывает не на этот сервер»** — см. ниже.

## Что-то подглючивает — перезагрузить сервер

- **Сервер отвечает** — `/reboot` в боте (затем `/reboot_confirm`) или кнопка «Перезагрузить сервер» в админке. Через 1–2 минуты бот напишет «🟢 Сервер перезагружен».
- **Бот не отвечает** — перезагрузите сервер в личном кабинете AmneziaHost. По SSH это делается командой `reboot` под root.

## 🔴 «Сервер недоступен» (проверка из GitHub)

1. Зайдите в личный кабинет AmneziaHost. Если VPS выключен или завис — включите или перезагрузите. После загрузки контейнеры поднимутся сами, бот напишет «🟢 Портал запущен», проверка — «🟢 Сервер снова доступен».
2. Если VPS работает, но из России недоступен — вероятно, **IP заблокирован**, см. ниже.
3. Если сервер не вернуть — **переезд** на новый VPS из бэкапа: README, «Переезд на новый VPS», 15–30 минут, ключи у семьи прежние.

## IP сервера заблокирован

1. Напишите тикет в AmneziaHost о смене IP.
2. Ждите в боте «🔄 IP сервера сменился: старый → новый»: сторож сам обновил DuckDNS.
3. Скажите семье выключить и включить VPN.

Если сообщения о смене IP нет, а IP точно сменился — проверьте командой `duckdns`.

## «🔄 IP сервера сменился»

Ничего делать не нужно: записи DuckDNS уже обновлены. Семье — выключить и включить VPN, если не подключается.

## «⚠️ Имя DuckDNS указывает не на этот сервер»

- **После переезда на старом сервере** — так и должно быть. Выключите старый сервер.
- **После переезда на новом**, если имена ещё не перенесены, — в админке: «Адрес сервера» → «Направить DuckDNS сюда».
- **Без всякого переезда** — запись изменил кто-то другой. Возможно, утёк токен DuckDNS (см. «Утекли секреты»). Верните имена кнопкой «Направить DuckDNS сюда» и смените токен.

## DuckDNS не работает или имя не находится

Уже поднятые туннели продолжают работать, новые подключения сервер не находят. Подождите: обычно DuckDNS возвращается сам. Если сбой долгий или имя заблокировали — нужно другое имя и перерисовка ключей (план, раздел 7.4). Перерисовка ещё не сделана в коде. Временно админ может подключаться по IP: в приложении Amnezia сервер добавлен по IP.

## «⚠️ Бэкап не сделан»

Причина — в сообщении. Частые:

- **Telegram недоступен** — пройдёт само, следующая попытка через час.
- **amnezia-api не отвечает** — `docker compose up -d`.
- **В образе нет age** — `docker compose up -d --build`.

Повторить сразу — `/backup` у бота. Журнал — `docker compose logs --tail 50 portal`.

## Продажи и ЮKassa

- **«⚠️ Заказ №N: ЮKassa не создала платёж»** — причина в сообщении. «не приняла ключи магазина» — ключи в `.env` неверные или перевыпущены (README, «Оплата через ЮKassa», шаг 3). «ЮKassa недоступна» — обычно проходит само; покупатель видит «Оплата сейчас недоступна» и может повторить.
- **«⚠️ Заказ №N: оплачено … вместо …»** — сумма платежа не совпала с заказом, доступ не выдан. Посмотрите платёж в личном кабинете ЮKassa; если всё в порядке — `/gift КОД ДНИ`, если нет — возврат в кабинете ЮKassa.
- **Покупатель пишет, что заплатил, а ссылки нет** — подождите минуту: портал проверяет платежи сам. Если долго — найдите платёж в ЮKassa по номеру заказа (он в описании платежа) и при необходимости `/grant НОМЕР`.
- **Покупатель просит вернуть деньги** — `/refund НОМЕР` (всё) или `/refund НОМЕР СУММА` (часть), затем `/refund_confirm`. Номер заказа — в `/sales`, во вкладке «Продажи» или в описании платежа в ЮKassa. Полный возврат уменьшает срок на срок заказа. «ЮKassa отклонила возврат» — причина в скобках; повторить можно, ключ идемпотентности после отказа меняется сам.
- **Закрыть продажу срочно** — вкладка «Продажи» → «Закрыть продажу». Купленный доступ продолжает работать, уже оплаченные заказы выполняются.

## «⚠️ Внешняя проверка доступности не приходила больше 2 часов»

GitHub, скорее всего, отключил расписание: так бывает, если в репозитории 60 дней не было изменений. GitHub → Actions → «Доступность сервера» → **Enable workflow**. Проверить — **Run workflow**.

## Админ потерял телефон или личную ссылку

- **Новая личная ссылка админа** — на сервере: `list` (узнать код админа), затем `relink КОД`. Прежняя ссылка перестанет работать.
- **Telegram под угрозой** — админка → «Telegram» → «Отключить». Затем в @BotFather `/revoke`, новый токен в `.env` (README, шаг 6) и в секрет GitHub `TELEGRAM_BOT_TOKEN`.

## Утекли секреты

| Что | Что сделать |
|---|---|
| Личная ссылка участника | Админка → «Новая ссылка» у участника. Ключи на его устройствах продолжат работать |
| Ключ VPN одного устройства | Отозвать устройство (в кабинете или в админке) и выдать новое |
| Токен бота | @BotFather → `/revoke`, новый токен в `.env` и в секрет GitHub |
| Секретный ключ ЮKassa | ЮKassa → Интеграция → Ключи API → перевыпустить, новый ключ — в `.env`, затем `docker compose up -d` |
| Токен DuckDNS | Сменить токен на duckdns.org, если сайт это позволяет. Новый — в `.env`, затем `docker compose up -d` |
| Закрытый ключ age | Создать новую пару (README, шаг 10), новый открытый ключ — в `.env`. Старые бэкапы считать раскрытыми: в них ключи сервера и все секреты, см. следующую строку |
| `.env` целиком или расшифрованный бэкап | Сменить токены бота и DuckDNS, ключ ЮKassa и `AMNEZIA_API_KEY`. Полная смена ключей сервера VPN означает новые ключи у всей семьи — делать, только если есть признаки, что ими пользуется кто-то чужой |

## Переезд и учения

- **Переезд на новый VPS** — README, «Переезд на новый VPS»: `server/scripts/restore.sh`.
- **Учения раз в квартал** — тот же скрипт с `--drill` на временном VPS. Рабочий сервер он не трогает.
