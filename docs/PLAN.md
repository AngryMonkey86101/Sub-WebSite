# План: Табор VPN — сервис выдачи VPN-ключей Amnezia

Цель — сайт, на котором члены семьи сами, без участия администратора, получают ключи AmneziaVPN для своих устройств. Ключи должны продолжать работать, когда у VPS меняется IP-адрес или когда сервер приходится перенести к другому хостеру.

План составлен 30.10.2026 по исходникам клиента AmneziaVPN 5.1.0.5 (коммит `7f9b7db` от 29.10.2026) и проекта [kyoresuas/amnezia-api](https://github.com/kyoresuas/amnezia-api) 2.0.0.

## 0. Принятые решения

| Вопрос | Решение |
|---|---|
| DNS | [DuckDNS](https://www.duckdns.org): бесплатные имена `*.duckdns.org`, IP обновляется HTTP-запросом |
| VPS | AmneziaHost (хостинг Amnezia) |
| Пользователи | 10–15 человек на старте, лимит по умолчанию — 4 устройства на человека, то есть до 60 ключей |
| Портал | На том же VPS, что и VPN |
| Персональные данные | Нет. Люди обезличены: только случайный код участника, никаких имён и контактов (раздел 8) |
| Протоколы | Пока только AmneziaWG. Xray (VLESS + REALITY) отложен: поддержка в портале есть, включается переменной `PROTOCOLS`, слушать будет TCP 8443 (порт 443 занят порталом) |
| Уведомления | Telegram-бот админу |

## 1. Коротко

1. **Подписок по URL в официальном приложении Amnezia для своего сервера нет.** Импорт ключей со своим `api_endpoint` (старый API v1) в 5.1 отключён: приложение отвечает ошибкой `LegacyApiV1NotSupportedError`. Новый механизм (API v2) работает только со шлюзом Amnezia: запросы шифруются публичным ключом, который вшит в приложение при сборке, поэтому свой шлюз вместо него не подставить. Значит, «подписка» для семьи — это ключ `vpn://`, который не нужно менять.
2. **Смена IP не требует новых ключей, если в ключе указано имя DuckDNS, а не IP.** Приложение заново определяет IP по имени при каждом подключении на всех платформах. На VPS работает сторож: при смене IP он сам обновляет запись в DuckDNS. В AmneziaHost IP меняется по тикету в поддержку — от администратора больше ничего не требуется.
3. **Переезд на новый VPS тоже не требует новых ключей.** Для этого нужно перенести ключи сервера и список клиентов из бэкапа и оставить прежний порт.
4. **Если придётся сменить само имя** (например, отказаться от DuckDNS), новые ключи на сервере не создаются. Портал заново собирает каждый ключ с новым адресом, и человек забирает его по своей личной ссылке.
5. **Рекомендуемый стек:** на VPS работают контейнеры Amnezia, `amnezia-api` (REST-доступ к ним), наш портал (Node 22 + SQLite + Caddy, как сервер групп Компаса) и сторож IP для DuckDNS. Раз в сутки делается зашифрованный бэкап, который хранится вне сервера.

## 2. Что известно об «API Amnezia», DuckDNS и AmneziaHost

### 2.1. Клиент AmneziaVPN: виды конфигураций

| Тип (`serverConfigUtils::ConfigType`) | Откуда берётся | Подходит нам |
|---|---|---|
| `SelfHostedAdmin` | Админ подключает свой сервер по SSH, приложение ставит Docker-контейнеры | Так устанавливается сервер |
| `SelfHostedUser` | Ключ `vpn://` без прав управления сервером | **Да: это ключ для члена семьи** |
| `Native` | `.conf` AmneziaWG/WireGuard, `vless://` и т. п. | Запасной вариант |
| `AmneziaFreeV3`, `AmneziaPremiumV2`, `ExternalPremium` | Шлюз Amnezia (`config_version: 2`, `api_config.service_type`) | Нет: шлюз закрыт вшитым ключом `PROD_AGW_PUBLIC_KEY` |
| `AmneziaFreeV2`, `AmneziaPremiumV1` | Старый API (`config_version: 1`, `api_endpoint`, `api_key`) | Нет: при импорте отклоняется |

### 2.2. Формат ключа `vpn://`

```
vpn:// + base64url_без_"="( uint32_BE(длина JSON) + zlib(JSON) )
```

Это формат Qt `qCompress`. Так же его кодирует amnezia-api в `src/helpers/encodeVpnConfig.ts`. JSON ключа `SelfHostedUser`:

```json
{
  "format_version": 1,
  "hostName": "k4tq9v.duckdns.org",
  "description": "Семья",
  "defaultContainer": "amnezia-awg2",
  "dns1": "1.1.1.1",
  "dns2": "1.0.0.1",
  "containers": [{
    "container": "amnezia-awg2",
    "awg": {
      "port": "…", "Jc": "…", "S1": "…", "H1": "…",
      "last_config": "{\"config\":\"[Interface]…Endpoint = k4tq9v.duckdns.org:…\",\"hostName\":\"k4tq9v.duckdns.org\",\"client_priv_key\":\"…\",…}"
    }
  }]
}
```

`last_config` — это JSON клиента, записанный строкой. В нём есть готовый текст `.conf`, адрес сервера, ключи клиента и параметры обфускации AWG (у AWG 3.1 добавились `HeaderProtectionKey`, `RekeyAfterTime`, `RandomTrailers` и другие).

Адрес сервера встречается в ключе трижды: в верхнем `hostName`, в `last_config.hostName` и в строке `Endpoint` текста `.conf`. Если поменять его во всех трёх местах и закодировать ключ заново, получится рабочий ключ на новый адрес. Сервер при этом трогать не нужно: он об адресе в ключе ничего не знает. На этом построена «перерисовка» ключей при смене имени (раздел 7.4).

### 2.3. Как устроен свой сервер (self-hosted)

| Контейнер | Протокол | Конфиг сервера | Таблица клиентов |
|---|---|---|---|
| `amnezia-awg2` | AmneziaWG 2.0 / 3.1 | `/opt/amnezia/awg/awg0.conf` | `/opt/amnezia/awg/clientsTable` |
| `amnezia-awg` | AmneziaWG 1.5 (legacy) | `/opt/amnezia/awg/wg0.conf` | `/opt/amnezia/awg/clientsTable` |
| `amnezia-xray` | VLESS + REALITY | `/opt/amnezia/xray/server.json` | `/opt/amnezia/xray/clientsTable` |

- **Добавление клиента в AWG.** В конфиг дописывается секция `[Peer]` (публичный ключ, PSK, `AllowedIPs = <IP клиента>/32`), затем выполняется `awg syncconf awg0 <(awg-quick strip …)` — без перезапуска, другие клиенты не отключаются. Отзыв: секция удаляется, и снова выполняется `syncconf`.
- **Добавление клиента в Xray.** Его UUID дописывается в `server.json`, а контейнер перезапускается — все клиенты Xray на несколько секунд отключаются.
- **Закрытый ключ клиента на сервере не хранится** (так устроен WireGuard). Чтобы показать ключ повторно или перерисовать его, портал должен хранить его сам, в зашифрованном виде.
- **IP сервера в серверных конфигах не записан.** Для AWG и Xray адрес в клиентском ключе — это ровно то, что админ ввёл при подключении сервера (`genBaseVars`: `$SERVER_IP_ADDRESS = credentials.hostName`). Если ввести имя, в ключах будет имя.
- **Клиент определяет IP по имени при каждом подключении.** На десктопе это `NetworkUtilities::getIPAddress` в `wireGuardProtocol.cpp` и `xrayProtocol.cpp`, на Android — `InetAddress.getByName(hostName)`, на iOS — строка `Endpoint = hostName:port`, которую разрешает WireGuardKit при запуске туннеля.
- **На десктопе клиент берёт первый адрес из ответа DNS** (`addresses.first()`). Поэтому у имени VPN не должно быть записи AAAA (IPv6): иначе устройство без IPv6 может получить IPv6-адрес и не подключиться.
- **Журналы.** Контейнеры Amnezia запускаются с `--log-driver none`, у Xray на сервере `loglevel: error` без журнала доступа. Подключения на диск не пишутся.

### 2.4. REST поверх серверов Amnezia: kyoresuas/amnezia-api

Независимый проект (MIT, Fastify/TypeScript, Docker-образ `ghcr.io/kyoresuas/amnezia-api`). Ставится на тот же VPS и работает с уже установленными контейнерами `amnezia-awg`, `amnezia-awg2` и `amnezia-xray`. Сервер при этом по-прежнему можно открывать в приложении Amnezia.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/clients` | Клиенты, трафик, последнее рукопожатие, online-статус |
| `POST` | `/clients` | Создаёт клиента и возвращает `vpn://` (`clientName`, `protocol`, `expiresAt`) |
| `PATCH` | `/clients` | Пауза и возобновление (`status`), срок доступа (`expiresAt`) |
| `DELETE` | `/clients` | Удаляет клиента |
| `POST` | `/clients/qr` | Серия QR-кодов в формате Amnezia (длинный ключ не помещается в один код) |
| `GET` / `POST` | `/server/backup` | Экспорт и импорт: `awg0.conf` с закрытым ключом сервера, PSK, `clientsTable`; у Xray — `server.json`, ключи REALITY и shortId |
| `GET` | `/server`, `/server/load` | Информация о сервере, нагрузка |
| `GET` | `/healthz`, `/metrics` | Проверка доступности, метрики Prometheus |

Что важно для нас:

- Авторизация — заголовок `x-api-key`. По умолчанию API отвечает по обычному HTTP, поэтому наружу его открывать нельзя.
- Адрес сервера в выдаваемых ключах задаёт `SERVER_PUBLIC_HOST`. Указываем в нём **имя DuckDNS**.
- При паузе клиенту ставится `AllowedIPs = 0.0.0.0/32`: ключ остаётся прежним, после возобновления снова работает.
- Журнал HTTP-запросов в API выключен (`disableRequestLogging: true`).
- `GET /clients` отдаёт и текущий IP устройства (`endpoint`). Портал это поле отбрасывает (раздел 8).
- В Docker-режиме контейнеру API пробрасывается `/var/run/docker.sock`, а это фактически root на хосте. Версию образа нужно фиксировать и читать изменения перед обновлением.

Рядом есть [kyoresuas/amnezia-protocols](https://github.com/kyoresuas/amnezia-protocols) — неинтерактивные установщики AWG 3.1, AWG 1.5 и Xray REALITY с той же раскладкой контейнеров, что у приложения. С ним новый сервер ставится скриптом, без графического приложения. Осторожно: флаг `--force` создаёт **новые ключи сервера**.

### 2.5. Кто ещё умеет подписки по URL

- **Приложение Amnezia** — не умеет (см. выше).
- **Xray-клиенты** (Happ, v2RayTun, Hiddify, Streisand, v2rayNG) — умеют: список `vless://` по ссылке с автообновлением. Это решает и смену имени, но только для Xray. Отмечено как необязательный этап 5.
- **v2RayTun**, по сообщениям на форуме ntc.party, импортирует ссылки `amneziawg://`. Не проверено.
- **3x-ui v3.7.0**, судя по описанию релиза, умеет AmneziaWG вместе с подписками. Это альтернатива, если отказаться от приложения Amnezia (раздел 3).

### 2.6. DuckDNS

Сайт duckdns.org из среды, где писался план, открыть не удалось. Поэтому пункты с пометкой «проверить» берутся из сторонних описаний и памяти, их нужно подтвердить на этапе 0.

- **Обновление записи:** `GET https://www.duckdns.org/update?domains=<имя1>,<имя2>&token=<токен>&ip=<IPv4>`. Ответ `OK` или `KO`. Есть параметры `ipv6`, `txt`, `clear` и `verbose`.
- **Токен один на весь аккаунт и управляет всеми его именами.** Кто знает токен, может перенаправить имена куда угодно. Токен хранится только на VPS в файле с правами `0600` (раздел 9). Проверить: можно ли перевыпустить токен в личном кабинете.
- **Вход** в DuckDNS — через сторонний аккаунт (GitHub, Google и т. п.). Для обезличенного сервиса лучше завести отдельный.
- **Лимиты:** на бесплатном аккаунте несколько имён (по памяти — до 5). Нам хватит двух. Проверить.
- **Вложенные имена** (`x.<имя>.duckdns.org`) по описаниям ведут на тот же адрес, что и `<имя>.duckdns.org`. Мы на это не полагаемся: берём два отдельных имени.
- **TTL записей** в документации не найден. Проверить на этапе 0: `nslookup -debug <имя>.duckdns.org`. От TTL зависит, как быстро устройства увидят новый IP.
- **Риски:** сервис бесплатный и держится на энтузиастах, бывают перебои. Пока DuckDNS не отвечает, новые подключения не находят сервер, а уже поднятые туннели продолжают работать. Сведений о блокировке `duckdns.org` в России в 2026 году поиск не нашёл. Проверить через [Cheburcheck](https://cheburcheck.ru) и с телефона без VPN.

### 2.7. AmneziaHost

Документацию docs.amnezia.org из среды, где писался план, открыть не удалось. Ниже — по выдаче поиска; подтвердить на этапе 0.

- **Смена IP:** по [FAQ Amnezia Hosting](https://docs.amnezia.org/ru/documentation/instructions/amnezia-hosting-faq) — только если адрес блокирует интернет-провайдер или какой-то сервис. Делается через тикет в поддержку из личного кабинета и, по [описанию сервиса](https://docs.amnezia.org/ru/documentation/instructions/amnezia-hosting), бесплатно. API для смены IP не найден.
- **Локации:** Нидерланды, Германия, Франция.
- **Проверить:**
  - есть ли root-доступ по SSH и можно ли ставить свои Docker-контейнеры;
  - можно ли держать сайт на портах 80 и 443;
  - не занят ли порт 443 уже установленным Xray;
  - есть ли у сервера IPv6.

Как это ложится на план: блокировка IP — это основной сценарий смены адреса. Админ пишет тикет, поддержка меняет IP, сторож на VPS за минуту-две обновляет DuckDNS, и семья продолжает пользоваться прежними ключами (раздел 7.1).

## 3. Варианты и выбор

| | A. amnezia-api + свой портал | B. Свой слой через `docker exec` | C. 3x-ui с подписками |
|---|---|---|---|
| Клиент у семьи | Приложение Amnezia | Приложение Amnezia | Happ / v2RayTun / Hiddify |
| Объём своей работы | Портал | Портал + управление контейнерами и формат `vpn://` | Почти ничего, но нет своего портала |
| Смена IP | Имя DuckDNS | Имя DuckDNS | Подписка + имя DuckDNS |
| Риски | Сторонний код с доступом к `docker.sock` | Свой код ломается при изменениях формата Amnezia | Другая экосистема, свои ограничения |

**Рекомендация: вариант A.** Портал работает с amnezia-api через тонкий адаптер (`server/src/amnezia.js`) с методами `createClient`, `listClients`, `setStatus`, `deleteClient` и `backup`. Если сторонний проект перестанут поддерживать, адаптер можно заменить на вариант B, не трогая остальной код.

## 4. Архитектура

```
 Член семьи (браузер)                         Приложение Amnezia
        │ HTTPS                                      │ UDP <порт AWG>
        ▼                                            ▼
  <имя-портала>.duckdns.org ──┐          <имя-vpn>.duckdns.org (только A-запись)
                              ▼                      │
 ┌──────────────────────── VPS AmneziaHost ──────────┼─────────────────────┐
 │  Caddy :443 ──► portal (Node 22, SQLite)           │                     │
 │                    │ http://amnezia-api:4001       ▼                     │
 │                    │ (внутренняя сеть Docker,  amnezia-awg2  amnezia-xray│
 │                    ▼  x-api-key)                   ▲                     │
 │               amnezia-api ── docker.sock ──────────┘                     │
 │                                                                         │
 │  сторож IP в портале (раз в минуту) ──► API DuckDNS                     │
 │  backup (раз в сутки) ──► age-шифрование ──► хранилище вне сервера      │
 └─────────────────────────────────────────────────────────────────────────┘
 Внешняя проверка (GitHub Actions по расписанию) ──► Telegram админу
```

- **Два независимых имени DuckDNS** со случайными названиями (например, `k4tq9v` и `m2pr7x`), без слов «vpn» и «family»:
  - `<имя-vpn>` — только в ключах. Сертификат для него не выпускается, поэтому имя не попадает в публичные журналы сертификатов (Certificate Transparency), где его могли бы найти сканеры.
  - `<имя-портала>` — для сайта. Caddy получает для него сертификат Let's Encrypt.
  - Сторож обновляет оба имени одним запросом.
- **Порты:** Caddy занимает TCP 80/443. AWG работает на своём UDP-порту. Xray — на TCP 8443, потому что 443 занят порталом.
- **Нагрузка:** 60 ключей — это четверть подсети AWG `/24` (253 адреса). Портал, API и Caddy занимают несколько сотен мегабайт памяти. Минимального тарифа, скорее всего, хватит; проверить по `/server/load` после запуска.

## 5. Данные портала (SQLite, `node:sqlite`)

| Таблица | Поля | Зачем |
|---|---|---|
| `members` | `id`, `code`, `role` (`admin` / `member`), `device_limit`, `status`, `created_at` | Участники. `code` — 4 случайных символа (например, `K7M2`) из алфавита без похожих букв. Имён нет |
| `invites` | `token_hash`, `member_id`, `created_at`, `expires_at` | Одноразовые приглашения (72 ч). Использованное удаляется |
| `access_tokens` | `token_hash`, `member_id`, `created_at` | Личные ссылки. Хранится только SHA-256, как в Компасе |
| `devices` | `id`, `member_id`, `number`, `platform`, `protocol`, `client_id`, `host`, `key_enc`, `created_at`, `revoked_at` | Устройства и ключи. `platform` — из фиксированного списка, свободного текста нет. `client_id` пуст, пока ключ создаётся; у отозванного устройства `key_enc` стирается |
| `events` | `id`, `at`, `type`, `member_code`, `details` | Журнал: выдан или отозван ключ, сменился IP, сделан бэкап |

- **`key_enc`** — ключ `vpn://`, зашифрованный AES-256-GCM. Ключ шифрования (`KEY_ENCRYPTION_KEY`) хранится в `.env`, а не в базе, поэтому утечка только файла базы не раскрывает ключи VPN.
- **`host`** — адрес, с которым собран ключ. По нему видно, какие ключи нужно перерисовать после смены имени.
- **Имя клиента на сервере Amnezia** — `K7M2-2` (код участника и номер устройства). В `clientsTable` на сервере больше ничего о человеке нет.

## 6. Сценарии

### 6.1. Приглашение (админ, один раз на человека)

1. Админ создаёт участника в админ-разделе портала или командой `node src/cli.js invite --devices 4`.
2. Портал выдаёт код участника, ссылку `https://<имя-портала>.duckdns.org/i/<токен>` и QR-код.
3. Ссылку админ передаёт лично. Кому какой код выдан, админ помнит сам или записывает у себя, не в портале.

### 6.2. Активация (член семьи)

Человек открывает ссылку и нажимает «Получить доступ» (само открытие ссылки приглашение не тратит: его открывают и предпросмотры мессенджеров). Приглашение удаляется, а человек получает личную ссылку `https://<имя-портала>.duckdns.org/m/<токен>`. Токен ещё сохраняется в cookie (`__Host-sid`, `HttpOnly`, `Secure`, `SameSite=Lax`, на год). Lax, а не Strict: иначе cookie не придёт, когда человек открывает личную ссылку из мессенджера. Формы защищены проверкой `Sec-Fetch-Site`/`Origin`. Страница предлагает сохранить ссылку в закладки или на экран «Домой».

Восстановить доступ по почте нельзя — почты нет. Если личная ссылка потеряна, админ выпускает новую ссылку для того же кода; старые ссылки перестают работать, а ключи на устройствах остаются.

### 6.3. Новое устройство (член семьи, без админа)

1. Человек выбирает платформу: iPhone/iPad, Android, Windows, macOS, Linux или Android TV.
2. Протокол по умолчанию — AWG (`amneziawg3`). Если включён Xray, есть вариант «если не подключается».
3. Портал проверяет лимит устройств и вызывает `POST /clients` с `clientName: "K7M2-2"`.
4. Ключ сохраняется в `devices`. Человек видит: кнопку «Скопировать ключ», QR-коды (через `/clients/qr`), ссылку на приложение в магазине и короткую инструкцию для своей платформы.
5. Из личного кабинета можно снова показать ключ и отозвать устройство (`DELETE /clients`, отключает сразу).

### 6.4. Админ-раздел

- Список участников (по кодам) и их устройств: онлайн или нет, давно ли было подключение, трафик. IP устройств не показывается.
- Пауза участника: `PATCH status: disabled` для всех его устройств. Удаление участника. Новая личная ссылка взамен потерянной.
- Состояние сервера (`/server/load`), текущий IP и время последней смены, журнал событий, дата последнего бэкапа.
- «Выдать ключ» — для тех, кому неудобно заходить на портал самим. Ключ хранится у админа в «Моих устройствах» с меткой «для кого» (до 40 символов, без обязательных имён). Метка есть только в базе портала: на сервере VPN ключ по-прежнему «код-номер», в Telegram и журнал событий она не попадает. Лимита устройств у админа нет.
- «Ключи вне портала» — ключи на сервере, которых нет в базе портала (выданы в приложении Amnezia): имя, протокол, состояние, сводка «всего / через портал / вне портала». Только для просмотра, имена не сохраняются.
- Доступ — по личной ссылке участника с ролью `admin`. Опционально — второй фактор (TOTP).

### 6.5. Подписка для Xray-клиентов (необязательно, этап 5)

`GET https://<имя-портала>.duckdns.org/s/<токен>` отдаёт список `vless://` в base64 с заголовками `profile-title`, `profile-update-interval` и `subscription-userinfo`. Ссылки собираются из `last_config` выданных Xray-ключей. Тогда при смене имени Xray-устройства подхватят изменения сами.

## 7. Смена IP и переезд

| Ситуация | Что делает система | Что делает админ | Ключи у семьи |
|---|---|---|---|
| IP заблокирован у провайдера | Сторож за 1–2 минуты обновляет DuckDNS, админ получает сообщение | Пишет тикет в AmneziaHost | Не меняются, достаточно переподключиться |
| Хостер сменил IP сам | То же | Ничего | Не меняются |
| Нужен другой хостер | Переезд скриптом `server/scripts/restore.sh` (раздел 7.2) | Запускает скрипт | Не меняются |
| DuckDNS долго не работает или заблокирован | Портал перерисовывает ключи под новое имя (раздел 7.4) | Заводит имя у другого DNS-провайдера, сообщает семье новый адрес портала | Перерисованные ключи забирают по личной ссылке |
| Утекли ключи сервера | Новые ключи сервера, все клиенты выпускаются заново | Запускает перевыпуск | Новые ключи по личной ссылке |

### 7.1. Сторож IP (`server/src/watchdog.js`, раз в минуту)

Сделан внутри портала, а не отдельным systemd-скриптом: чат бота и журнал событий лежат в базе портала, а портал перезапускается Docker сам. Ставить на хост ничего не нужно, токен DuckDNS — в `.env` (права `0600`).

1. Узнаёт внешний IPv4 у трёх независимых сервисов (`api.ipify.org`, `ipv4.icanhazip.com`, `checkip.amazonaws.com`) и верит адресу, который назвали хотя бы два.
2. Смотрит, куда ведут имена VPN и портала (DNS, запись A).
3. Если имя ведёт на **прежний IP этого сервера**, отправляет `https://www.duckdns.org/update?domains=<имя-vpn>,<имя-портала>&token=…&ip=<IPv4>` и ждёт ответа `OK`. Следующие 10 минут ждёт, пока кэши DNS отдадут новый адрес, и запрос не повторяет.
4. IPv6 не передаёт, запись AAAA остаётся пустой (раздел 2.3).
5. Пишет событие в журнал портала и отправляет сообщение в Telegram: «IP сервера сменился: старый → новый».
6. **Чужую запись не трогает.** Если имя ведёт на адрес, которого у этого сервера не было, сторож только предупреждает. Направить имя сюда — кнопка в админке или `cli duckdns --takeover`. Это заменяет флаг «активный сервер»: при переезде старый и новый серверы не перезаписывают DuckDNS друг за другом.
7. О сбоях (сервисы IP, DNS, DuckDNS) сообщает, если они длятся дольше 10 минут. Токен DuckDNS не попадает ни в журналы, ни в сообщения.

Ограничения:

- Уже поднятый туннель новый IP не узнает: WireGuard не переопределяет адрес по имени на ходу. Пользователю нужно выключить и включить VPN — это пишем в инструкции для семьи.
- Пока у DNS-серверов провайдера не истёк кэш (TTL), часть устройств может ещё несколько минут получать старый IP.
- При строгом kill switch в выключенном состоянии DNS может не работать. Если не подключается — отключить kill switch, подключиться, включить обратно.
- Сертификат Caddy и выкладка из GitHub Actions от смены IP не зависят: `SERVER_HOST` — это имя портала, а `known_hosts` записан по имени.

### 7.2. Переезд на новый VPS (`server/scripts/restore.sh`) — сделан

Нужен, если AmneziaHost не подходит или сервер потерян. Новый VPS можно взять у AmneziaHost или у другого хостера. Скрипт запускается на новом сервере под root из клона репозитория; на вход — бэкап из Telegram, закрытый ключ age он спрашивает. Пошагово — server/README.md, «Переезд на новый VPS».

1. Ставятся Docker (официальный установщик), age, jq, git, ufw. Создаётся пользователь `deploy`.
2. Бэкап расшифровывается. Ключ и расшифрованные файлы удаляются в конце, даже при ошибке.
3. Фаервол: порт SSH текущего подключения, 80/443 и UDP-порт AmneziaWG из `awg0.conf` бэкапа.
4. AmneziaWG ставится с **теми же портом и подсетью**: `amnezia-protocols/install.sh awg --port <P> --subnet <S> --cidr <C>`. Версия установщика закреплена коммитом.
5. Портал: `.env` из бэкапа со своими `DOCKER_GID` и `DOCKER_API_VERSION`, база — на том портала. Команда `cli restored` забывает состояние старого сервера: сторож не трогает DuckDNS до явного переноса, бэкап ждёт восстановления ключей, иначе в нём оказались бы новые пустые ключи.
6. `cli restore-vpn` загружает ключи через `POST /server/backup`: `awg0.conf` с закрытым ключом и маскировкой, PSK, `clientsTable` и `syncconf`. Затем контейнер AmneziaWG перезапускается — `start.sh` берёт подсеть из восстановленного `awg0.conf`. Проверки: публичный ключ сервера совпадает с бэкапом, число клиентов тоже.
7. По подтверждению `cli duckdns --takeover` направляет имена на новый сервер, и только потом запускается Caddy. Если запустить Caddy раньше, Let's Encrypt отказал бы и временно заблокировал выпуск сертификата. Старый сервер, если ещё работает, видит, что имя ведёт не на него, и запись не трогает. Перенос обратим кнопкой в админке старого сервера.

SSH-ключи хоста не переносятся: если настроена выкладка из GitHub, обновляется `SERVER_KNOWN_HOSTS`. Xray скрипт не восстанавливает (отложен).

**Учения:** `restore.sh --drill` на временном VPS. Бот и сторож там выключены, имена не трогаются — рабочий сервер не задет. Цель: переезд меньше чем за 30 минут, ключи у семьи не меняются.

### 7.3. Бэкап (`server/src/backup.js`, раз в сутки) — сделан

Сделан внутри портала, как и сторож IP: расписание, бот и база уже там.

- **Что входит:**
  - ответ `GET /server/backup`: `awg0.conf` с закрытым ключом сервера и параметрами маскировки, PSK, таблица клиентов;
  - копия базы портала (`VACUUM INTO` — целостная и при работающем портале);
  - настройки `.env`, кроме зависящих от сервера (`DOCKER_GID`, `DOCKER_API_VERSION`).

  SSH-ключи хоста не входят: портал в контейнере их не видит.
- **Шифрование:** `age` (пакет Alpine в образе портала) открытым ключом админа из `BACKUP_AGE_RECIPIENT`. Закрытый ключ на сервере не хранится. Без ключа бэкап не делается вовсе.
- **Куда:** файлом в Telegram-чат админа (`sendDocument`, без звука). Старые копии бот удалить не может — Telegram позволяет ботам удалять только сообщения младше 48 часов, — их чистит админ.
- **Неудача** бэкапа — сообщение в Telegram (одно на полосу неудач), новая попытка через час.
- **Вручную:** кнопка в админке, `/backup` у бота, `cli backup --stdout` — архив в файл на сервере.

### 7.4. Перерисовка ключей при смене имени (`node src/cli.js rehost --host <новое-имя>`)

1. Админ меняет `SERVER_PUBLIC_HOST` в amnezia-api — новые ключи сразу собираются с новым именем.
2. Портал расшифровывает каждый действующий ключ, заменяет адрес в трёх местах (раздел 2.2; у Xray — адрес в настройках подключения), кодирует ключ заново и сохраняет с новым `host`.
3. На сервере ничего не меняется: пиры и ключи те же.
4. В личном кабинете у устройств со старым адресом появляется пометка «Обновите ключ»: удалить сервер в приложении и вставить ключ заново.

### 7.5. Мониторинг

- **Снаружи (сделано):** GitHub Actions раз в 15 минут открывает `https://<имя-портала>.duckdns.org/healthz` (`server/scripts/monitor.mjs`). Если ответа нет, проверка повторяется каждую минуту в течение 5 минут, затем админу уходит сообщение в Telegram. Пока сервер недоступен, раз в час приходит напоминание, а когда он вернётся — сообщение об этом. Состояние между запусками — результат прошлых запусков: ошибка значит «сервер недоступен».
- **Обратная проверка (сделано):** портал отмечает приход внешней проверки. Если её не было больше 2 часов, он предупреждает админа. Причина: GitHub отключает расписание в репозитории, где 60 дней не было изменений.
- **Доступность из России** (необязательно): проверка порта через API [check-host.net](https://check-host.net) с российских узлов. Если адрес перестал открываться — сообщение «похоже, IP заблокирован, напишите тикет в AmneziaHost».
- **Внутри:** портал раз в 5 минут проверяет `amnezia-api /healthz` и статус контейнеров.
- **Сообщения в Telegram:** сменился IP, сервер недоступен, бэкап не сделан, диск заполнен больше чем на 85 %. В сообщениях только коды участников.
- **Бот админа (сделан):** чат подключается одноразовой ссылкой из админки, сообщения бот забирает длинным опросом (входящих подключений нет). Команды — `/status`, `/members`, `/invite`, `/relink КОД` — только из подключённого личного чата. Ссылку админа бот не выдаёт: Telegram-аккаунт админа даёт право приглашать, но не входить в админку.

## 8. Обезличивание: что и где хранится

| Где | Что хранится | Чего нет |
|---|---|---|
| База портала | Коды участников, хеши токенов, платформы устройств, зашифрованные ключи, журнал событий по кодам | Имён, телефонов, почты, IP-адресов |
| Сервер Amnezia (`clientsTable`, `awg0.conf`) | `K7M2-2`, дата создания, публичный ключ и внутренний IP туннеля | Чего-либо о человеке |
| Память WireGuard (`awg show`) | Последний внешний IP каждого устройства — так работает протокол, на диск не пишется | — |
| Журналы | Caddy без журнала запросов (как в Компасе), портал не пишет IP (ограничение частоты — только в памяти), у amnezia-api журнал запросов выключен, у контейнеров VPN `--log-driver none` | IP-адресов и истории посещений |
| Страницы портала | Всё встроено в страницу | Внешних шрифтов, CDN и аналитики: браузер не обращается к третьим сторонам |
| Telegram и бэкапы | Коды участников, одноразовые приглашения из бота, зашифрованный архив. В базе портала — id чата админа | Имён, меток устройств и IP |

Аккаунты DuckDNS и AmneziaHost — это аккаунты админа. Члены семьи нигде не регистрируются.

## 9. Безопасность

- **amnezia-api:**
  - работает только во внутренней сети Docker, порт наружу не публикуется;
  - ключ API — `openssl rand -hex 32`;
  - образ зафиксирован по версии (`2.0.0`), обновление — только после чтения изменений.
- **Токен DuckDNS** хранится в `/etc/family-vpn/duckdns.env` (владелец root, права `0600`) и в зашифрованном бэкапе. Если он утечёт, чужой человек сможет перенаправить имена:
  - для VPN это только отказ в обслуживании: чужой сервер не пройдёт рукопожатие без ключей;
  - для портала это возможность подменить сайт и собрать личные ссылки.
  
  Что делать при утечке: перевыпустить токен в DuckDNS, проверить записи, выпустить всем новые личные ссылки.
- **Портал:**
  - токены хранятся как SHA-256;
  - лимит частоты запросов;
  - проверка `Origin` на POST;
  - ключи VPN зашифрованы (раздел 5).
- **Фаервол:** открыты TCP 22 (только по ключу), TCP 80 и 443, UDP 443 (HTTP/3), UDP-порт AWG и, если нужен, TCP-порт Xray.
- **Секреты** (`.env`, ключ API, токен DuckDNS, токен Telegram-бота) — только на сервере и в зашифрованном бэкапе. В репозитории — только `.env.example`.

## 12. Риски и открытые вопросы

**Риски**

- **amnezia-api — сторонний проект с доступом к `docker.sock`.** Меры: фиксированная версия, заменяемый адаптер, формат `vpn://` описан выше (вариант B реализуем).
- **Формат ключей Amnezia меняется** (`format_version`, AWG 3.1). Перед обновлением amnezia-api или приложения — проверка: выдать ключ и импортировать его в свежую версию приложения.
- **DuckDNS — бесплатный сервис без гарантий.** Меры: уже поднятые туннели переживают короткие перебои; при долгом сбое — другое имя и перерисовка ключей (раздел 7.4).
- **Блокировка имени или подмена DNS у провайдера.** Меры: случайные имена, имя VPN не попадает в журналы сертификатов, перерисовка ключей.
- **Смена IP в AmneziaHost — вручную, через тикет.** Пока поддержка не ответила, сервер недоступен. Мера: мониторинг доступности из России (раздел 7.5), чтобы узнать о блокировке раньше семьи.
- **Активный туннель не узнаёт новый IP** — в инструкции для семьи пишем «выключить и включить».

**Решено:** уведомления — через Telegram-бота. Xray отложен (поддержка в коде оставлена).

**Если DuckDNS не находится из России.** 31.10.2026 при добавлении сервера в приложение Amnezia по имени DuckDNS подключение не прошло. Причина выясняется: неверная запись на duckdns.org, запись IPv6 или DNS провайдера (диагностика — server/README.md, «Не подключается по имени DuckDNS»). Если окажется, что DNS провайдеров не находят имена DuckDNS, план Б — своё доменное имя у DNS-хостинга с API, который доступен из России. Сторож IP (этап 3) тогда обновляет запись через API этого хостинга, остальной план не меняется.

## 15. Диспетчер в РФ: новый VPS при блокировке

**Почему.** IP серверов блокируют за несколько дней — и с AmneziaWG, и с Xray на 443 при небольшом трафике (оба у Zomro). Похоже на блокировку адресов хостера, а не на распознавание протокола. Вместо борьбы за один IP — одноразовые серверы: заблокировали — заказать новый и переехать автоматически.

**Решения (12.11.2026):**

| Вопрос | Решение |
|---|---|
| Где диспетчер | Свой VPS в РФ: проверяет доступность изнутри страны, как её видит семья |
| Хостер серверов VPN | Zomro, API BILLmanager (`api.zomro.com`, функции `v2.instances.*`), аренда посуточно (`order_period=-50` — проверить на шаге 0) |
| Смена сервера | Плановая раз в 3 дня в 04:00 МСК (тёплая, со старым на связи, перекрытие 20 часов) и внеплановая при блокировке (холодная, из часового бэкапа) |
| Новый сервер | Собирается с нуля, ключи VPN — из бэкапа |
| Имена DuckDNS | Прежние: после переезда диспетчер направляет их на новый IP |
| Модуль хостера | Заменяемый: можно добавить второго хостера, если заблокируют подсети Zomro целиком |

**Концепция (13.11.2026): плановая смена раз в 3 дня + внеплановая при блокировке.**

- **Плановая (тёплая), ночью, раз в 3 дня:** заказать VPS → проверить новый IP из РФ (не открывается — удалить и заказать другой, до 3 попыток) → подготовить сервер (Docker, AmneziaWG с ключами из последнего бэкапа, портал не запущен) → заморозить старый: финальный бэкап, остановка портала и Caddy (бот, оплаты, сторож), AmneziaWG работает → завершить на новом: база из финального бэкапа, портал и бот, DuckDNS на новый IP → проверка из РФ (не прошла — откат: разморозить старый, вернуть имена, удалить новый) → перекрытие N часов → удалить старый через API. Данные не теряются, новый IP проверен до переключения, есть откат.
- **Внеплановая (холодная):** старый недоступен из РФ — финальный бэкап не снять; берётся последний часовой, старый выключается через API (чтобы не было двух ботов), дальше как в плановой. Отсчёт 3 дней — заново.
- **Расписание (решено 13.11.2026):** плановая смена в 04:00 МСК раз в 3 дня, перекрытие 20 часов — старый сервер удаляется в 00:00 МСК следующих суток.
- **Открытые вопросы:** переподключаются ли устройства к новому IP сами за время перекрытия (проверить на учениях); как Zomro списывает посуточную плату.
- **Сертификат портала** переносится со старого сервера при плановой смене: иначе лимит Let's Encrypt — 5 одинаковых сертификатов в неделю.

**Ключи VPN при переезде (решено 12.11.2026): из бэкапа.** VPS и система каждый раз новые, а ключи сервера AmneziaWG и список клиентов переносятся из свежего бэкапа, как в `restore.sh`. Ключи у семьи и покупателей прежние: после переезда достаточно выключить и включить VPN. Поэтому диспетчеру нужен свежий бэкап до блокировки (этап 2): с заблокированного сервера из РФ его уже не забрать.
